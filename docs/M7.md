# M7 · 成本与上下文面板 · 内置浏览器预览

> 目标：把「这一轮模型花了多少钱、上下文都被什么占满了」变成随时能翻的账；
> 把「agent 改出来的页面到底长什么样」变成点一下就能看到的画面。
>
> **状态：已实现（v0.9.0）。** 方案保留供维护对照；实施结果与偏离见 §12。

## 0. 为什么是这两件事

M1–M6 解决的是「能不能把活干完」：工具、审批、回滚、工作流、定时任务、MCP 与技能。
现在这套东西在真实任务里跑起来，最大的两个盲区变成了：

1. **花了多少，不知道。** 输入框底部只有一行按字符数猜出来的 `tokens` 与上下文百分比，
   它在「中英混排 + 大段工具结果」上误差很大，也没有单价、缓存命中、逐轮对比。
   定时任务无人值守地跑，预算只管墙钟、节点数与步数，**没有一个按 token 计的硬门**。
   用户问「这一晚花了多少」时，现在答不上来。
2. **改完长什么样，要自己开浏览器。** agent 跑完 `npm run dev` 后输出一句
   `Local: http://localhost:5173/`，人还得切出去、复制、粘贴、刷新。前端任务里，
   「看一眼页面」是最高频的验收动作，现在它不在工作流里。

M6 还留了两处尾巴，正好被「预览」接住：MCP 工具返回的图片只落盘、聊天里只剩一行占位；
MCP 的 `resources` 没有查看入口。M7 给它们一个统一的 artifact 预览浮层，完整的资源浏览页
仍留到 M7.5。

所以 M7 的两半也是配套的：**成本/上下文给人「信任」，预览给人「反馈」**。

## 2. 范围与非目标

**做**：

- **用量采集**：每次模型调用记录输入/输出/缓存命中 tokens、耗时、步号、模型与来源
  （`provider` 真实值 / `estimate` 估算值）；一轮对话与整个任务可汇总。
- **上下文面板**：把「模型实际收到的请求」拆成系统提示、技能目录、历史、本轮消息、
  工具结果、工具 schema 六类，显示 token 数、占比、窗口余量与每步增量。
- **成本面板**：按模型单价算本轮/本任务/近 7 天费用（统一美元显示；多币种换算留到以后），
  价格可在设置覆盖；所有金额标「参考」，与账单无关。
- **预算**：无人值守增加 `maxTokens` 硬门（默认 1,000,000）；`maxCost` 可选，默认 0 = 不设。
  超限在**下一个模型调用之前**中止，并按预算超限失败关闭。
- **内置浏览器预览**：右侧可收起的预览抽屉，加载本机 dev server；
  URL 栏、后退/前进/刷新、三种宽度、缩放、在系统浏览器打开、截图存 artifacts。
- **导航策略**：默认只允许 loopback（`localhost` / `127.0.0.1` / `[::1]`，任意端口）；
  外部站点需一次显式确认，且按任务记住（只在内存里）；`window.open`、下载、权限请求一律拒绝。
- **URL 发现**：从命令输出与工具参数里识别 `http://localhost:1234` 之类的地址，
  在对应工具卡上给一个「在预览中打开」按钮（只建议，不自动打开）。
- **artifact 预览**：工具卡里的图片/音频缩略图，点开浮层；MCP `resource` 的文本也走同一浮层。
- **界面**：对话区用量抽屉、设置里的价格/窗口覆盖与数据清理、工作流运行面板与报告、
  计划页预算字段、预览抽屉与浮层。
- **离线自检**：mock 端点的 usage 四种模式（有 / 无 / 拒绝 `stream_options` / 中途断开）+
  用量与预算自检 + 预览导航策略纯函数测试 + 无头 Electron 预览 smoke。

**不做（留到 M7.5 / M8）**：

- **模型自己开浏览器**：M7 不给模型任何 browser / navigate 工具。预览只服务于人；
  模型能驱动浏览器是另一种能力（也是另一种风险），需要单独的设计与审批。
- 把预览截图作为**图片消息**喂给模型：现在的 API 消息只有字符串，支持视觉输入要改协议与
  模型选择逻辑，M8 再谈。截图只落 artifacts、给人看。
- **完整 MCP resources / prompts 浏览与引用页**：M7 只做工具结果里的预览浮层，
  列目录、订阅、把资源插进上下文留给 M7.5。
- 自动上下文压缩/摘要：M7 只负责把账摊开并在 80% / 95% 提醒；压缩策略本身是 M8 的题。
- **预览范围**：只预览本机 HTTP 服务（dev server / `npx serve` 这类）。
  直接打开工作区的 `file://` HTML 不在 M7 内：Chromium 的 file 源能读到工作区外的东西，
  要开就先用本地服务器，避免再发明一套文件围栏。
- 多标签页预览、远程/局域网预览、录制与交互回放、按站点持久登录态。
- 在浏览器里跑 `dev:web` 时没有 WebContentsView：用量面板可用（走估算），
  预览入口隐藏并提示「内置预览需要桌面端」；不影响构建与页面截图脚本。
- 用量账单对账、自动充值、按模型路由到不同端点。
- 渲染层直接读任意本地文件（artifact 预览只走白名单协议）。

## 3. 关键设计决定

### D1 用量以「真实 usage 优先、估算兜底」，来源必须可见

不同 OpenAI 兼容端点的用量返回并不统一：有的只在最后一个 chunk 给 `usage`，
有的完全不返回，有的在中断时什么都不给。所以采集分三层：

1. 请求带 `stream_options: { include_usage: true }`；若端点返回 400/422 明确不认这个字段，
   **去掉它重试一次**，并把该端点记为「不支持 usage」。
2. 流里任何位置出现 `usage` 就采用（`prompt_tokens` / `completion_tokens` /
   `prompt_tokens_details.cached_tokens`）。
3. 没有真实值就估算：CJK 字符按 1 token、其余按 4 字符 1 token 粗算，并标 `estimate`。
   中断/失败但已经收到部分输出时，标 `partial: true`。

界面上真实值与估算值用不同颜色/后缀区分（`12.4k` vs `≈12.4k`），**不把估算写成账单**。

### D2 上下文面板对齐「模型实际收到的请求」

面板不统计 UI 里有多少字，而是让主进程在每次请求前把 `messages` 与 `specs` 交给计数器：

- 六类：`system`（规则 + 工作区树）、`skills`（技能目录）、`history`（最近 12 条历史消息的纯文本）、
  `turn`（本轮用户文本、助手文本与 tool_calls；思考只用于展示、不进请求，不计入）、
  `toolResults`（工具返回，含 12k 截断后的实际内容）、
  `toolSchemas`（本轮注册表里全部工具的 JSON Schema 序列化）。
- 真实 `prompt_tokens` 存在时，把它当作**总量真值**，六类按估算比例归一；
  否则总量也标估算。这样「总量对了、构成是估的」比「总量和构成都错」更诚实。
- 每步记录一份快照，所以能看到「第 3 步读了 400 行文件后，上下文从 22% 跳到 61%」。
- 窗口来自模型目录（默认 128k）；未知模型走设置里的默认窗口。到 80% 黄、95% 红，
  提示「另开任务 / 先让它总结」——M7 不自动截断，截断规则只展示。

### D3 成本是参考值，不是账单

- 模型目录内置一份**带日期与来源的参考价**（输入/输出/缓存命中，每百万 token，美元），
  设置页可逐项覆盖；端点自报的模型名与目录对不上时，用「自定义模型」的空白价格，
  这时只显示 tokens，不显示金额。
- 价格存主进程的 `<userData>/pricing.json`（设置页经 IPC 读写），**不能只放渲染层**：
  无人值守的费用预算在调度器里执行，那时没有界面在场。账本只落 tokens、不落金额，
  显示时按当前价格表实时折算，改价后历史金额跟着变，并在界面注明「按当前参考价」。
- 统一标注「参考价 · 更新于 xxxx-xx-xx」，并说明缓存命中的折扣可能不适用于该端点。

### D4 预览用 WebContentsView，独立分区，而不是 iframe

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| `<iframe>` | 布局简单、天然在 DOM 里、可被弹层盖住 | 大量站点 `X-Frame-Options` / CSP 禁止内嵌；dev server 常带 `frame-ancestors`；无法可靠截图与处理弹窗 |
| `<webview>` 标签 | DOM 内嵌、z 序友好 | Electron 官方不推荐，需要开 `webviewTag`，历史漏洞多，行为随版本漂移 |
| **WebContentsView（推荐）** | 独立的 webContents 与 session 分区、可截图、可精细控制权限/导航 | 原生视图浮在 HTML 之上，弹层盖不住；需要渲染层上报 bounds |

选 WebContentsView，并用两条约束消化它的代价：

- 预览固定在右侧停靠区，应用内的菜单/审批条/主题选择器都不覆盖那块区域；
  任何全屏浮层（例如未来的确认框）打开时，渲染层通知主进程把预览临时移出。
- bounds 由渲染层用 `ResizeObserver` 上报（`x/y/width/height/visible`），主进程节流到 ~60fps；
  `visible=false` 时把 view 从 `contentView` 摘掉，不靠透明度硬藏。

预览使用**独立持久分区** `persist:olivia-preview`：不共享应用会话 cookie，
但保留 dev server 的登录态；设置里提供「清除预览数据」。预览销毁即释放 webContents。

### D5 预览默认只开 loopback，外部站点一次性放行

预览加载的是本机 dev server，它往往是一个**正在开发、可能被依赖包污染**的页面。
所以默认：

- 允许 `http(s)://localhost[:port]`、`http(s)://127.0.0.0/8`、`http(s)://[::1]`，路径与查询任意；
- 允许 `about:blank` 作为初始页；`file:`、`javascript:`、`data:`、`blob:` 导航一律拒绝；
- 其他 host 需要点一次「仍要打开」，按钮旁写明风险；**只对该任务、本次会话**记住；
- `window.open` / `target=_blank` 不新开预览页：loopback 地址在同一视图里打开，
  外部地址确认后交给系统浏览器；
- 所有权限请求（摄像头、麦克风、定位、通知、剪贴板读、MIDI、串口……）一律拒绝；
  下载一律取消并提示「预览不接管下载」。

这套判断做成 `packages/core/src/preview.ts` 里的纯函数（`classifyPreviewUrl(url, policy)`），
主进程只是执行者，便于脱离 Electron 单测。

### D6 预览只给人看，M7 不给模型浏览器工具

预览是一个**人机反馈环**，不是 agent 的能力扩张。M7 明确不加
`browser.open` / `browser.screenshot` 这类工具；模型最多能从命令输出里得到那个 URL
（本来就有），但打不打开、看不看截图由人决定。

这样做的理由：一旦模型能驱动浏览器，就等于给了它访问本机所有 HTTP 服务的能力
（包括路由后台、内部面板），审批粒度、SSRF 面、页面里的提示注入都要重新设计。
M7 先解决 80% 的「我自己要看一眼」，把模型驾驶留到有专门方案的时候。

### D7 artifact 预览走自定义协议 + realpath 白名单

MCP 图片现在只存路径，渲染层拿不到内容；直接开 `file://` 或让 IPC 读任意路径都不行。

- 主进程注册 `olivia-artifact://` 协议（启动前 `registerSchemesAsPrivileged`，标记
  `standard`/`secure`/`supportFetchAPI`），只服务 `<userData>/artifacts/` 下的真实文件：
  `path.resolve` + `fs.realpath` 后必须仍在该目录内，符号链接指向外部一律 403。
- 只按扩展名给 MIME（png/jpg/webp/gif/svg/wav/mp3/txt/md/json），未知类型下载为附件；
  目录、无扩展名、超过 25MB 的文件拒绝。SVG 以 `attachment` 返回，界面只在 `<img>` 里显示，
  不导航到它，避免 svg 里的脚本在应用源里执行。
- 应用 CSP 允许 `img-src`/`media-src` 使用该协议；预览视图不注册这个协议（它不需要）。
- 不做缩略图生成：图片用 CSS 限制尺寸，音频用原生 `<audio>`，文本只读前 256KB 并标截断。

### D8 无人值守把 token 预算做成硬门，成本预算可选

- `UnattendedPolicy.maxTokens`（默认 1,000,000）按整轮工作流累计的 `input+output` 计；
  每次拿到 usage 就累计，超限立刻置 `budgetHit` 并在**下一次模型调用前**中止。
- 已经在执行的工具（例如一个写入）不强行打断，避免半截文件；中止点在调用边界。
- `maxCost` 默认 0 = 不设。只有设置了有效价格才允许填，填了就在超限时同样中止，
  报告里写明「按参考价折算」。
- 报告新增「用量」段：输入/输出/缓存、按模型分组、参考费用、是否触预算。

### D9 面板是输入框上方的可收起抽屉，不新开一页

信息就在产生它的地方：对话底部状态条点开一个贴在输入区上方的抽屉（默认收起，约 420px 高），
不跳页、不挡对话。抽屉分两个 tab：**上下文**与**用量**；工作流页在自己运行面板里显示汇总，
计划页在运行记录里显示用量与预算结果。这样不需要在侧栏再加一个「用量」入口，
也避免「看账单」和「读对话」成为两个割裂的场景。

## 4. 数据模型

```ts
// packages/core/src/usage.ts
export type UsageSource = 'provider' | 'estimate';

export interface TokenUsage {
  input: number;
  output: number;
  /** 命中缓存的输入 token；端点不返回则为 undefined */
  cached?: number;
  source: UsageSource;
  /** 中断/失败但已有部分输出 */
  partial?: boolean;
}

export interface ContextPart {
  key: 'system' | 'skills' | 'history' | 'turn' | 'toolResults' | 'toolSchemas';
  tokens: number;
  /** 原始字符数，用于「这一块是 3 个文件还是 1 个」的说明 */
  chars: number;
  items: number;
}

export interface ContextSnapshot {
  window: number;
  used: number;
  parts: ContextPart[];
  source: UsageSource;
}

export interface UsageStep extends TokenUsage {
  step: number;
  at: number;
  durationMs?: number;
  context: ContextSnapshot;
}

export interface TurnUsage {
  taskId: string;
  turnId: string;
  model: string;
  steps: UsageStep[];
  input: number;
  output: number;
  cached: number;
  estimated: boolean;
}

export interface ModelPricing {
  /** 每百万 token 的美元参考价 */
  inPerM: number;
  outPerM: number;
  cachedInPerM?: number;
  currency: 'USD';
  updatedAt: string;
  /** 内置还是用户覆盖 */
  source: 'builtin' | 'user';
}
```

模型目录扩展（`types.ts`）：

```ts
export interface ModelInfo {
  id: string;
  label: string;
  short: string;
  /** 上下文窗口；未知模型回退 settings.defaultContextWindow */

  pricing?: ModelPricing;
}
```

`Settings` 增加窗口回退值：

```ts
export interface Settings {

  /** 未知模型的窗口回退，默认 128_000 */
```

事件日志扩展（`session.ts`，每步一条，重放忽略即可）：

```ts
    step: number;
    model: string;
```

`UnattendedPolicy` 增加：

```ts
/** 整轮 token 上限（输入+输出），默认 1,000,000 */
maxTokens: number;
/** 按参考价折算的费用上限（美元），0 = 不设 */

```

## 5. 实现细节

### 5.1 usage 采集

```text
请求：{ stream: true, stream_options: { include_usage: true }, ... }
流解析：
  任意 chunk 带 usage → 记下（最后一次优先）
  无 usage 且正常结束 → estimate(messages 文本, 输出文本)
  端点显式拒绝 stream_options（400/422 且错误文案含 stream_options/unknown field）
    → 去掉该字段重试一次，并把 baseUrl 标记为「该端点不报用量」
```

- `usage` 字段可能出现在 `choices: []` 的最后一个 chunk 里，解析时不能因为
  `choices` 为空就跳过；`prompt_tokens_details.cached_tokens` 与部分端点的
  `prompt_cache_hit_tokens` 都读。
- 每次调用（每步）只记一条 `usage`；一个回合的总量是各步相加。
- 估算系数放 `packages/core/src/usage.ts`，配一条注释与自检用例；
  真实 usage 可用时，用真实 `prompt_tokens` 归一上下文构成，不直接采用估算总量。

### 5.2 上下文构成

在 `runAgentLoop` 每步调用 `streamCompletion` 之前，把当时的 `messages`、`specs`、
技能目录交给 `measureContext()`：

- `system`：第一条 system 消息的实际内容（工作区树最多 40 项）；
- `skills`：技能目录段落（最多 30 个名字）；
- `history`：`options.history.slice(-12)`（渲染层已过滤成纯文本）；
- `turn`：本轮新增的 user 文本、assistant 文本与 `tool_calls` 参数（思考只在界面展示，不进请求）；
- `toolResults`：`role:'tool'` 消息的内容（已按 12k 字符截断）；
- `toolSchemas`：`JSON.stringify(specs.map(s => ({name, description, parameters})))`。

面板明确写出两条既有截断规则：「历史只带最近 12 条」「单个工具结果最多 12,000 字符」，
并给一个「为什么我看到的不等于模型收到的」说明——避免用户拿界面字数对不上账。

### 5.3 持久化与聚合

- `session.jsonl` 追加 `usage` 事件（失败/中断也落一条，带 `partial`），重启重放时
  时间线不变；`replaySession` 只认 user/assistant 事件，新增类型天然被忽略。
- 另写一份轻量账本 `<userData>/usage.jsonl`：每步一行（不含对话内容，只有
  taskId/turnId/model/step/tokens），用于「近 7 天」「按模型」的快速聚合与 CSV 导出；
  文件按 5MB 轮转一次。账本与价格表分离，金额永远按**当前价格表**实时折算。
- 价格表在 `<userData>/pricing.json`：主进程提供 `olivia:pricing.get / set / reset`，
  preload 暴露 `pricing`；设置页经 IPC 读写，无人值守预算与金额展示共用同一份。
  浏览器 `dev:web` 没有主进程时回退到 core 里的内置参考值（只读）。

### 5.4 成本计算

```text
cost = input/1e6 * price.inPerM
     + output/1e6 * price.outPerM
     − cached/1e6 * (price.inPerM − price.cachedInPerM)
```

- 保留 4 位小数，小于 $0.0001 显示 `<0.0001`；
- 没有价格（未知模型 / 用户清空）时只显示 tokens；
- 计算做成 `packages/core` 的纯函数 `costOf(usage, pricing)`，主进程预算与渲染层展示共用；
- 聚合按 `(taskId, turnId, step)` 唯一，避免同一回合在对话页、工作流与账本里重复计费。

### 5.5 预算与门禁

- 工作流：`runAgentTurn` 的 `usage` 事件回调里累加 `runTokens`；超过 `maxTokens` 时
  设置 `budgetHit = 'token 超过上限 …'`，`runAbort.abort()`，与现有墙钟/步数预算走同一条
  `finish()` 失败路径，报告里给明确原因。
- 计划：`UnattendedPolicy` 新字段进 Schedules 详情表单（带默认值与解释），
  老计划缺字段时回退 `DEFAULT_UNATTENDED_POLICY`。
- 交互式对话**不设**硬预算，只在抽屉里提示；是否要「交互式也拦」留作以后。

### 5.6 预览宿主（主进程）

```ts
const view = new WebContentsView({
  webPreferences: {
    partition: 'persist:olivia-preview',
    sandbox: true,
    contextIsolation: true,
    nodeIntegration: false,
    webviewTag: false,
    spellcheck: false,
    // 不挂 preload：预览页拿不到 window.olivia
  },
});
mainWindow.contentView.addChildView(view);
view.setBounds({ x, y, width, height });
view.webContents.loadURL(url);
```

- IPC：`preview.open / close / navigate / back / forward / reload / set-bounds / set-zoom /
  allow-external / clear-data / capture`，全部带 `taskId`，主进程只允许当前窗口的预览；
- 事件：`olivia:preview.event` 推送 `PreviewState`（url/title/loading/canGoBack/error/external）；
- 生命周期：任务切换或离开对话页 → 销毁 view；应用退出 → 清空分区？不，保留登录态，
  只有「清除预览数据」才清；
- 弹层遮挡：预览区固定在右侧，渲染层的全屏浮层出现时调用 `preview.set-bounds({visible:false})`；
- 缩放：`webContents.setZoomFactor`；宽度预设只改 view 宽度并居中，不做 UA/DPR 伪造
  （需要真机模拟时再上 CDP `Emulation.setDeviceMetricsOverride`，M7 不做）。

### 5.7 导航与权限策略

- `will-navigate` / `will-redirect`：先 `classifyPreviewUrl`；`deny` 直接 `event.preventDefault()` 并
  在状态里写原因；`external` 弹确认（渲染层发起 `allow-external` 后才放行），否则转系统浏览器；
- `setWindowOpenHandler`：返回 `{ action: 'deny' }`，loopback 目标在同一个 view 里 `loadURL`，
  外部目标走系统浏览器（需确认）；
- `session.setPermissionRequestHandler`：全部拒绝，记录一条日志；
- `will-download`：`event.preventDefault()` 并提示；
- `certificate-error`：不忽略，直接失败并显示；
- 地址栏只展示，不允许直接输入 `file:`；输入后仍走同一 `classifyPreviewUrl`。

### 5.8 URL 发现

- 从 `run_command` 的 stdout/stderr、工具 args 与 `command.output` 里匹配
  `https?://(localhost|127\.0\.0\.1|\[::1\])(:\d+)?(/[^\s]*)?`；
- 先剥 ANSI 颜色码与尾部标点；同一地址去重；
- 只在工具卡上显示「在预览中打开」，**永不自动打开**；
- 已打开过的地址在同一任务里记住，作为地址栏下拉建议（仅内存）。

### 5.9 截图与 artifact 预览

- `view.webContents.capturePage()` → PNG 存 `<userData>/artifacts/preview_<task>_<ts>.png`，
  截图后打开 artifact 浮层，可复制路径/在系统里打开；
- MCP 工具结果：`ToolRun.artifacts` 渲染成 3 个缩略图 + 「还有 N 个」，点开浮层；
- 浮层用 `olivia-artifact://` 地址，右键菜单不放开「另存为任意路径」；
- 清理：设置里「清理预览与 artifacts」按日期删除；单文件 25MB 上限。

### 5.10 CSP

应用渲染层补：

```html
<meta http-equiv="Content-Security-Policy"
  content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
           img-src 'self' data: olivia-artifact:; media-src 'self' olivia-artifact:;
           font-src 'self' data:; connect-src 'self'; object-src 'none';
           base-uri 'none'; frame-src 'none'" />
```

- dev 模式由 Vite 的 HMR 需要 `connect-src 'self' ws://127.0.0.1:5273`；
  通过主进程按 `isDev` 注入或构建时替换，生产包保持严格值；
- 应用只加载本地 `dist`，模型请求在主进程，所以 `connect-src` 不需要外域；
- 预览视图不注入任何 CSP，也不注册 artifact 协议。

## 6. 安全与隐私模型（一张表看完）

| 能力 | 应用窗口 | 预览视图 | artifact 协议 |
| --- | --- | --- | --- |
| Node / preload | 仅 preload 暴露的 `window.olivia` | 无 preload、无 Node | 不适用 |
| 进程隔离 | 默认 sandbox + contextIsolation | `sandbox: true` + contextIsolation | 主进程内 |
| 会话 | 应用默认分区 | 独立 `persist:olivia-preview`，与应用 cookie 隔离 | 不适用 |
| 网络 | 只加载本地 dist；模型请求在主进程 | 默认仅 loopback；外部需一次确认 | 不适用 |
| 权限 | 不申请 | 全部拒绝（摄像头/麦克风/定位/通知/剪贴板读…） | 不适用 |
| 文件 | 经 IPC 与围栏 | 无文件能力 | 仅 `<userData>/artifacts` 内真实文件 |
| 下载 | 不涉及 | 取消 | 不适用 |
| 模型可驱动 | 否 | **否（M7 无浏览器工具）** | 否 |

硬约束：

- 预览页里的内容**永远不进入模型上下文**（除非人手动复制文本）。
- artifact 协议不接受目录、`..`、绝对路径、符号链接逃逸；HTML/SVG 按附件下载而不是渲染
  （避免在应用源里执行脚本；需要看 SVG 时用 `<img>`，脚本不执行）。
- 预览截图只落本地 artifacts，不上传、不自动附加。
- 用量账本不含提示词/代码内容，只有计数与模型名。

## 9. 风险与取舍

| 风险 | 处理 |
| --- | --- |
| 端点不返回 usage，估算误差大 | 标 `estimate`、用真实总量归一构成、面板写明误差来源；不把估算当账单 |
| 价格表过时或与代理实际计费不同 | 标参考价与日期、可逐项覆盖、未知模型不出金额 |
| 预览加载的本机 dev server 可能被依赖包投毒 | 独立分区、无应用 API、权限全拒、默认 loopback、外部需确认 |
| 外部站点在应用内打开，扩大攻击面 | 默认禁止；一次性确认；地址栏高亮；不注册 artifact 协议；CSP 收紧 |
| WebContentsView 浮在 HTML 上盖住弹层 | 固定右侧停靠；全屏浮层时隐藏；bounds 同步；离开路由销毁 |
| 预览窗口常驻内存 | 单实例、切任务销毁、无多标签 |
| 无人值守被 token 预算打断在工具中间 | 只在模型调用边界中止；已发出的写操作等它完成 |
| CSP 破坏 Vite HMR 或内联样式 | 开发模式单独放行 ws；样式用 `unsafe-inline`；构建后 smoke 一次 |
| artifact 协议变成任意文件读取 | realpath 白名单 + 只读 + MIME 白名单 + 大小上限 + 不做目录列表 |
| 截图/图片误入模型上下文 | M7 不实现图片输入；截图与 artifacts 只给人看 |

`olivia-artifact://` 白名单预览；MCP 图片/音频/资源浮层；工作流/计划用量与报告；
Vite 构建期 CSP（dev 放宽 HMR，生产严格）；浏览器 dev 模式隐藏预览入口。

**实施时敲定 / 偏离的地方**：

- **中断的流不记 partial 用量**：流读到一半报错时，这一轮直接判失败，不落半条 usage；
  「没有 `[DONE]` 也没有 usage」的响应按正常结束 + 估算处理。`mock-llm --usage=partial`
  覆盖的是后者。
- **预览截图依赖可见显示表面**：`capturePage()` 在无头/离屏窗口会报
  `Current display surface not available for capture`；预览截图按错误提示返回，不崩溃。
  `preview-e2e` 在无头环境跳过图像校验，可见窗口下走同一路径。
- **外部站点放行只在内存里按任务记录**：没有持久域名白名单，关掉预览/重启应用即忘。
- **预览设备预设只改 view 宽度**（桌面铺满 / 平板 768 / 手机 390），不做 UA 与 DPR 伪造。
- **成本只显示美元**；内置两份参考价是示例值（`updatedAt` 2026-11-01），设置页可逐项覆盖，
  金额永远按当前价格表重算，不写进账本。
- **`pricing.json` 由主进程管**，浏览器 `dev:web` 只能读内置值；设置页的保存/导出/清理在浏览器里禁用。
- **预览不注册到浏览器页面**：`olivia-artifact` 协议只挂在应用默认 session，预览分区拿不到。
- **`stream_options` 回退**只针对 400/422 且错误文案命中 `stream_options` / `unknown field`；
  其它错误照常失败，避免掩盖真正的参数错误。
- **工作流的 `maxCost` 需要先有价格**；未配置价格时只按 token 预算拦，报告里会写明「只统计 token」。
