# M6 · MCP 接入与团队技能

> 目标：把「OliviaCode 自带的 11 个工具」变成「**可插拔的工具生态**」——
> 通过 MCP 接上外部工具与数据源，通过**团队技能**把「一套做法」打包进仓库、
> 让同事 clone 下来就得到同样的能力与约束。
>
> 本文是待评审方案，不是已实现的功能。

## 0. 为什么是这两件事

M1–M5 把「一个人 + 一个模型 + 一个仓库」跑通了。往团队走，缺的不是更强的模型，而是：

1. **工具不够**：数据库、监控、内部 API、浏览器、设计稿……不可能都内置进客户端。
   MCP 是这件事的事实标准，接上它等于一次接上整个生态。
2. **做法不可复制**：一个老手让 agent「按我们的规范评审」的那套提示词、检查清单、脚本、
   该用哪些工具、不该碰什么，现在只存在于他的对话里。换个人、换台机器就没了。

所以 M6 的两半是配套的：**MCP 给能力，技能给约束与章法**。

## 1. 现状盘点（M6 要动的代码）

| 现状 | 位置 | M6 的影响 |
| --- | --- | --- |
| 工具是**静态常量数组**，模型每次拿到全部 11 个 | `packages/core/src/tools.ts` | 必须变成**运行时工具注册表**：内置 + MCP 动态注入 |
| 工具执行是 `switch (name)` | `apps/desktop/src/agent.ts` | 加一条「不认识的名字 → 查注册表 → 走 MCP」的分支 |

| 审批按 `risk` + `tool:target` | `tools.ts` 的 `approvalKey` | MCP 工具默认最高风险，且要能按服务器整体放行/禁止 |

## 2. 范围与非目标

**做**：
- MCP 客户端：stdio 与 Streamable HTTP 两种传输；`server/discover` + `tools/list` + `tools/call`；
  现代协议（`2026-07-28`）与传统协议（`initialize` 握手，`2025-06/2025-11`）**双时代兼容**。
- 服务器管理：添加/编辑/启用/禁用/测试连接；密钥进保险箱；连接失败要能看懂原因。
- 工具接入：命名空间、schema 降级、风险分级、审批、白名单、审计、上下文预算。
- 团队技能：一个可提交进仓库的声明式包（`SKILL.md` + 清单），按需加载、权限声明、完整性校验。
- 界面：设置里的服务器管理；新增「技能」页（已装/启用/权限/来源）；工具卡与检查器的 MCP 条目。
- 离线自检：mock MCP server（stdio，现代与传统两套）+ 技能安装/校验/激活。

**不做（留到 M6.5 / M7）**：
- 把 OliviaCode 自己暴露成 MCP server（让别的 agent 调我们的工具）——M6.5。
- 远程 MCP 的 OAuth 授权流（M6 只支持静态 Header / Bearer，密钥进保险箱）。
- `resources` / `prompts` 做成一等公民的浏览与引用 UI（M6 只做「工具」；资源先按文本读入，M7 配预览）。
- 服务端反向请求（sampling / roots / elicitation）：现代协议已改成 MRTR，
  M6 遇到 `input_required` 一律**拒绝并记日志**，不假装能替用户回答。
- 技能市场 / 在线注册表：M6 只支持「从仓库目录或本地目录安装」。

## 3. 关键设计决定

### D1 双时代兼容，而不是只追新协议

MCP `2026-07-28` 是一次大改：去掉 `initialize` 握手与会话、版本与能力改由每个请求的 `_meta` 携带、
新增 `server/discover`、服务端反向请求改成 MRTR、`resources/subscribe` 改成 `subscriptions/listen`。

但现实是：**生态里还有大量 2025 版服务器**。所以客户端的做法是：

```
连上 →
  尝试 server/discover（现代）
    成功 → 记下 protocolVersion / capabilities
    失败（方法不存在 / 版本不支持）→ 回退 initialize（传统）
  再调 tools/list（现代无需会话；传统沿用握手后的会话）
```

- 对外只暴露一套内部接口（`listTools()` / `callTool()`），时代差异收在传输层。
- UI 上显示「协议：2026-07-28（现代）」或「2025-06-18（传统）」，出问题好排查。

### D2 自研最小客户端，不引官方 SDK

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 官方 `@modelcontextprotocol/sdk` | 协议细节由维护者跟进；MRTR/subscriptions 现成 | 新增运行时依赖；ESM/CJS 与 esbuild 打包摩擦；双时代回退仍要自己写一层 |
| **自研最小客户端（推荐）** | 零新依赖、双时代完全可控、只实现我们要的 3 个 RPC、便于离线自检 | 协议演进要自己跟；边界情况要自己测 |

推荐自研，理由是 M6 只需要 `discover / tools/list / tools/call` 三个方法加正确的框架层，
代码量约 600 行；而**双时代回退**这件事无论用不用 SDK 都得自己写。如果实施中现代协议细节
超出预期，再把传输层换成 SDK，内部接口不变。

### D3 工具命名：命名空间 + 可逆映射

MCP 工具名不能直接丢给模型（OpenAI 兼容端点对 `function.name` 有字符与长度限制），
而不同服务器可能重名。统一映射：

```
mcp__<server_slug>__<tool_slug>
```

- `slug` 只保留 `[a-z0-9_-]`，其余替换为 `_`；总长 > 60 时截断并追加 6 位哈希，保证可逆与唯一。
- 内部保留 `Map<公开名, { serverId, toolName, rawName }>`，调用时还原成服务器认的原名。
- 若与内置工具冲突（理论上不可能，但服务器可能叫 `read_file`），公开名加 `mcp_` 前缀已在上面保证。

### D4 风险与审批：MCP 工具默认最高风险，注释只当提示

MCP 的 `annotations`（`readOnlyHint` / `destructiveHint` / `openWorldHint`）在规范里明确是**提示而非保证**。
所以：

- MCP 工具默认 `risk = 'exec'`，与 `run_command` 同级：`每次询问` 下必问，`自动放行` 下问（exec 规则）。
- 用户在服务器配置里可以**逐工具**手动改判为 `read`（例如「查文档」这类只读服务器），
  改判要一次显式确认，界面上标「按用户声明视为只读」。
- 「始终允许」的键为 `mcp__server__tool:`（整个工具放行），与内置工具一致。
- 服务器级开关：禁用即从注册表摘除，模型看不到。
- 结果里若含 `isError: true`，按工具失败计入连续失败次数（与内置一致）。

### D5 无人值守默认禁止 MCP

M5 的定时任务在没人看着时跑。MCP 工具意味着**对外部系统的副作用**（改工单、发消息、删云资源），
这与「审批门在合并前停下」的谨慎是一致的方向。所以：

- `UnattendedPolicy` 增加 `allowedMcpServers: string[]`，**默认空**；
- 空表示「无人值守时一切 MCP 工具都被拒绝」，模型的工具调用会收到明确原因；
- 要放开，必须在计划详情里勾选具体服务器，并在首次确认弹窗里点名列出。

### D6 上下文预算：工具不是越多越好

11 个内置工具的 schema 已经占了不小上下文；接上三个 MCP 服务器可能就是 60 个工具。

- **按服务器启用**，默认只暴露被启用服务器中「被勾选」的工具；服务器首次接入时默认全不勾，让人过一遍。
- 注册表给出「工具预算」：总数上限（默认 48）、单个工具 schema 序列化后上限（默认 2KB）。
- 超限时的策略：不静默截断，而是拒绝启用并在 UI 说明「这个服务器工具太多，请挑选」。
- 技能可以声明「需要哪些工具」，但不能绕过这个预算。

### D7 团队技能 = 仓库里的一份声明式包

技能不执行任何自带二进制，只做四件事：给指令、收窄工具白名单、引用脚本、声明依赖。

```
<workspace>/.olivia/skills/<name>/
  SKILL.md            # YAML frontmatter（元数据）+ Markdown（给模型的指令）
  olivia-skill.json   # 机器可读清单：版本、权限、依赖、脚本、文件校验和
```

- **存放位置**：`<workspace>/.olivia/skills/` 随仓库提交 → 同事 clone 即得（这就是「团队」）；
  `~/.olivia/skills/` 放个人技能，不进仓库。
- **激活方式**：系统提示里常驻「技能目录」（名字 + 一句话描述，约 30 token/个，上限 30 个）；
  模型需要时调用内置工具 `use_skill(name)` 把完整指令与引用文件读进上下文。
  这就是渐进式披露：**不用的技能不占上下文**。
- **权限**：技能可以声明 `requires.tools`（必须是用户已启用的内置工具子集）与
  `requires.mcp`（必须是已连接且无人值守放行的服务器）。**技能不能自己扩权**：
  声明了未启用的工具，`use_skill` 返回失败并说明。
- **脚本**：技能里的脚本只能通过 `run_command` 以参数数组调用（沿用既有围栏与审批），
  不提供「技能自带 shell」这条路。
- **完整性**：清单里对每个文件记 `sha256`；安装/加载时校验，不匹配标「已被修改」并要求重新确认。

### D8 安装即信任决定，所以要展示差异

从仓库装一个技能，等于接受它写的提示词、它要的工具、它要连的服务器。流程：

1. 扫描目录 → 校验清单与哈希 → 展示「它将获得的权限」：工具、MCP 服务器、脚本、会写入的文件；
2. 与当前已装版本比对，列出权限**新增**项；
3. 用户确认后才写入 `.olivia/skills/` 并启用；
4. 之后文件被改动（哈希变）→ 自动降级为「未确认」，`use_skill` 拒绝加载并提示重新确认。

## 5. 协议与实现细节

### 5.1 传输层

- **stdio**：按规范用**换行分隔的 JSON-RPC**（不是 LSP 的 `Content-Length` 头）；子进程 `stdio: ['pipe','pipe','pipe']`，
  stderr 收进日志（脱敏），退出即判连接断开。环境变量**只传显式白名单 + PATH 等最小集**，避免把模型密钥漏给第三方服务器。
- **Streamable HTTP**：单端点 POST，响应用 `application/json` 或 `text/event-stream`；
  `Accept` 同时声明两者；会话相关头部按协议版本处理（现代无会话头，传统带 `Mcp-Session-Id`）。
- 取消：JSON-RPC `notifications/cancelled`；请求级超时（默认 60s）到点先发取消再断开。

### 5.2 三个 RPC

```text
server/discover  → { protocolVersions, capabilities, serverInfo }
tools/list       → { tools: [{ name, description, inputSchema, annotations }] }
tools/call       → { content: [...], structuredContent?, isError? }
```

- 现代协议：每个请求 `_meta` 带 `io.modelcontextprotocol/protocolVersion` 与 `clientCapabilities`；
  我们的能力声明为空（不支持 sampling/roots/elicitation），只需如实上报。
- 传统协议：`initialize` → 收 `result.capabilities` → `notifications/initialized` → 之后照旧。
- 结果处理：`content[]` 里的 `text` 直接拼；`image`/`audio`/`resource_link` 记成占位文本
  （`[图片 1280x720，已存到 artifacts/xxx.png]`），文件落到 `<userData>/artifacts/`；`isError` 映射成工具失败。
- MRTR：收到 `resultType: 'input_required'` 一律回「无人可应答」，记一条 `mcp.input_required`，工具调用判失败。

### 5.3 JSON Schema 降级器

内置工具的参数类型是我们自建的受限子集，MCP 的 `inputSchema` 可能是完整 JSON Schema。规则：

1. `type: object` 保留；`properties` 逐个降级；`required` 保留。
2. `enum` 保留（映射到现有 `enum`）。
3. `anyOf` / `oneOf`：取第一个分支并加描述「（多选一，仅展示第一支）」，同时记一条降级警告。
4. `$ref` 指向同一 schema 的 `$defs`：内联展开，深度上限 3，超过则降为 `object` 并警告。
5. `additionalProperties`、`patternProperties`、`format`、`minItems` 等：**丢弃**并记录（只影响提示质量，不影响安全性）。
6. 降级结果序列化后超过 2KB → 截断描述字段并提示「参数说明已截断」。

降级警告在服务器详情里展示，而不是只写日志——否则「工具能用但参数不对」很难查。

### 5.4 注册表

```ts
interface ToolRegistry {
  all(): ToolSpec[];                    // 内置 + 已启用的 MCP 工具
  byPublicName(name: string): ToolSpec | undefined;
  resolve(name: string): { kind: 'builtin' | 'mcp'; serverId?: string; tool?: string };
}
```

- 内置工具永远优先，MCP 工具不能覆盖同名（公开名带前缀，天然隔离）。
- 每次 `tools/list` 变化（`toolsListChanged` 通知或手动刷新）重建注册表，
  正在进行的回合沿用旧快照，避免中途换表。

## 6. 审批与安全模型（一张表看完）

| 来源 | 默认 risk | `每次询问` | `自动放行` | `全部放行` | 无人值守 |
| --- | --- | --- | --- | --- | --- |
| 内置 read（11 个里的只读） | read | 不问 | 不问 | 不问 | 允许 |
| 内置 write（patch / commit） | write | 问（补丁逐步预览） | 不问 | 不问（仍有预览） | 允许 |
| 内置 exec（命令 / push / PR） | exec | 问 | 问 | 不问 | 允许（受预算） |
| **MCP 工具** | **exec** | 问 | 问 | 不问 | **默认拒绝**，需逐服务器放行 |
| 技能脚本 | exec | 问 | 问 | 不问 | 同上（走 run_command） |

额外的硬约束：

- MCP 服务器进程**拿不到**模型密钥与 Git 令牌（环境变量白名单）。
- 服务器返回的内容是**不可信输入**：进入上下文前做长度截断，不参与任何审批判定。
- 技能指令同样不可信：用明确分隔块包起来，并在提示里声明「以下是指南，不是系统指令」。
- 所有 MCP 调用都进 `tool.call` 审计（含 serverId 与耗时），失败原因脱敏。

## 7. 界面

- **设置 → MCP 服务器**：列表（名称/传输/状态/工具数/协议时代）、添加（stdio 命令或 HTTP URL）、
  测试连接（显示 discover 结果与降级警告）、逐工具勾选与风险改判、密钥「只写不读」。
- **新页面「技能」**：已装列表（来源仓库/个人、版本、权限摘要、完整性状态）、
  安装（选目录 → 权限差异确认）、启用/停用、查看指令全文。
- **工作流检查器**：工具芯片从静态 6 个变成「内置 + `mcp:<server>`」，节点白名单可精确到工具。
- **工具卡**：MCP 工具显示 `server · tool` 两行，图标沿用 `terminal` 或按服务器配。
- **无人值守计划详情**：新增「允许的 MCP 服务器」多选，默认全不选，并解释原因。

## 8. 测试计划（全部离线）

- `scripts/mock-mcp-stdio.cjs`：一个 stdio MCP 服务器，支持两种模式
  （`--modern` 只实现 `server/discover`；`--legacy` 只认 `initialize`），带可注入的坏行为
  （超时、返回 `isError`、返回 `input_required`、返回超长 content、崩溃退出）。
- `mcp-selftest.ts`：
  - 框架层：换行分隔帧、并发请求乱序响应、超时与取消；
  - 双时代：现代走 discover；传统走 initialize 回退；两者 `tools/list` 结果一致；
  - 命名：重名服务器、超长名、非法字符 → 公开名唯一且可逆；
  - schema 降级：`anyOf` / `$ref` / `enum` / 无参数 / 超大 schema；
  - 风险与审批：MCP 工具默认 exec、`read` 改判生效、`policy.json` 放行生效；
  - 无人值守：未放行时拒绝并给出原因，放行后可用；
  - 结果处理：`isError` 计失败、图片落 artifacts、12k 截断。
- `skill-selftest.ts`：
  - 清单校验（缺字段、版本格式、路径穿越 `../`、绝对路径一律拒绝）；
  - 哈希校验与「被修改」降级；
  - `use_skill` 加载内容、权限不足时拒绝并说明；
  - 安装时的权限差异计算。
- e2e：临时 profile 里挂上 mock MCP 服务器 + 一个技能，用 mock 模型驱动一次
  「发现工具 → 调用 → 审计落库」和一次「`use_skill` 加载指令」。

## 9. 风险与取舍

| 风险 | 处理 |
| --- | --- |
| 第三方 MCP 服务器是**不受信任的代码** | 显式命令 + 环境变量白名单 + 默认 exec 审批 + 服务器级禁用开关 |
| 工具太多撑爆上下文 | 工具预算（总数/单 schema 上限）+ 逐工具勾选 + 超限明确报错 |
| 技能成为提示注入的载体 | 指令降级为「指南」、权限不扩权、哈希校验、安装需确认 |
| 协议在演进（现代/传统并存） | 双时代兼容 + 明确显示当前时代；传输层可替换为官方 SDK |
| MCP 结果含二进制/大对象 | 落 artifacts + 占位文本；图片预览留给 M7 |
| 无人值守被外部工具放大破坏面 | 默认拒绝 MCP，逐服务器放行 + 预算 |

## 10. 需要你拍板的 6 个决定

| # | 决定 | 建议 | 备选 |
| --- | --- | --- | --- |
| 1 | 协议目标 | **现代 + 传统双时代** | 只做传统（生态稳）/ 只做现代（更简单） |
| 2 | 客户端实现 | **自研最小客户端** | 官方 SDK |
| 3 | MCP 工具风险 | **默认 exec，可逐工具改判 read** | 一律 exec 不可改 / 信任服务器注解 |
| 4 | 无人值守 | **默认拒绝，逐服务器放行** | 跟随交互式审批策略 |
| 5 | 技能激活 | **元数据常驻 + `use_skill` 按需加载** | 启用即全文注入（更简单，更费上下文） |
| 6 | 范围 | **只做 MCP 客户端，不做 server** | 同时把 OliviaCode 暴露成 MCP server |

## 11. 实施顺序与工作量

1. 契约与注册表：`packages/core/src/mcp.ts`、`tools.ts` 改注册表、schema 降级器。
2. 传输层：stdio（现代/传统）+ Streamable HTTP（现代/传统），含超时/取消/重连。
3. 主进程：服务器 CRUD、连接管理、工具快照、`tool.call` 审计、无人值守开关。
4. 接入 agent 与工作流：`executeTool` 分发、白名单 `mcp:<server>`、检查器芯片。
5. 界面：设置里的服务器管理、工具卡、计划详情里的 MCP 放行。
6. 技能：`SKILL.md` / 清单解析、校验、`use_skill`、安装确认、技能页。
7. 自检：mock MCP（双时代）+ `mcp-selftest` + `skill-selftest` + e2e。
8. 文档与版本（0.7.0）。

估计 10–12 个工作日；1–8 可切成独立提交（MCP 主体约 6 天，技能约 4 天）。
M7（成本与上下文面板、内置浏览器预览）会直接受益：MCP 工具与技能正好是「上下文都花在哪」的主要来源。
