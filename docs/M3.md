## M2：改动的粒度

**逐处接受**：`apply_patch` 不再「全收全拒」。主进程先把每条 `edits` 校验唯一命中，生成独立预览，发 `file.proposed`，界面上每处一个勾选框；用户勾完点「应用选中」，主进程只把选中的那几条写进文件，再发 `file.changed` 把卡片切成「已应用」。

- 校验不过（找不到 / 不唯一）直接报错，让模型重读，不会模糊套用。
- 写入前快照照旧，只是快照发生在「用户确认之后」。

**多步回滚**：快照不再用完即弃。

- 每份快照带 `undone` 标记，`latest()` 只取最新未撤销的一份。
- 卡片上的按钮从「撤销这次写入」改成「回滚到这一步之前」：恢复该快照，并把它之后的所有快照一并作废。
- 撤销提示里给出「还能回退 N 步」，连续点不同卡片上的回滚按钮即可一步步退回。

## M3：Git

### 能力

| 区域 | 行为 |
| --- | --- |
| 绑定 | 「选择已有仓库」或「克隆远程仓库」（HTTPS + 令牌） |
| 状态 | 分支、upstream、ahead/behind、逐文件状态（M/A/D/R/?/U） |
| 改动 | 展开看 hunk，勾选后「暂存选中」；也可整文件暂存 / 取消暂存 |
| 提交 | 提交信息 + 「全部暂存」；只提交暂存区 |
| 分支 | 下拉切换、新建 |
| 同步 | 拉取（`--ff-only`）、推送（`origin HEAD`，永不 force） |
| PR | 标题/描述草稿 → 目标分支 → 创建，返回链接 |
| 对话里 | `git_commit` / `git_push` / `git_create_pr` 三个工具，走同一套审批 |

### 认证

- 令牌用 Electron `safeStorage` 加密存到 `%APPDATA%/oliviacode/credentials.bin`，界面只能覆盖/清除，读不回原文。
- 调 git 时不把令牌写进 URL，也不写 `.git/config`：命令子进程通过 `GIT_CONFIG_*` 环境变量注入 `http.extraHeader: Basic base64(user:token)`，进程结束即失效。
- 同时设置 `GIT_TERMINAL_PROMPT=0`、`credential.helper=`，避免系统凭据管理器接管。
- 所有 git 输出、错误信息都过一遍脱敏：`https://user:pass@` → `https://***@`，令牌串替换成 `***`。

### 分支与 PR 的边界

- 默认分支保护：M3 不提供 force push、`reset --hard`、删除分支。
- 拉取失败若产生冲突，返回冲突文件清单，提示去编辑器处理，不做三方合并 UI。
- PR 的 provider 通过 remote host 判断：`github.com` → GitHub API；其余 → GitCode API v5。

## PR 链路实跑（GitCode）

用真实令牌对 `Olivia0703/OliviaCode` 跑了一遍端到端：

```
vault.set: {"ok":true}
vault.status: {"gitcode":true,"github":false}
clone: {"ok":true,"dir":".../olivia-prws-AsiXXI"}
state: {"branch":"olivia-m3-verify","remote":{"provider":"gitcode",...}}
.git/config has token: false
push: {"ok":true}
pr: {"ok":true,"url":"https://gitcode.com/Olivia0703/OliviaCode/merge_requests/1"}
```

- 令牌只经环境变量进入子进程，克隆下来的 `.git/config` 里搜不到令牌。
- PR 号与页面地址均由 API 返回的 `number` 拼出（GitCode 的页面路径是 `merge_requests/<n>`）。
- 验证完成后已关闭 PR、删除测试分支，仓库里只留一条已关闭记录。

## 已知限制

- PR 已在 GitCode 实跑；GitHub 的接口形状同构，但没有用真实令牌验证过。
- 克隆只支持 HTTPS + 令牌，SSH 密钥托管留到后续。
- 逐 hunk 暂存基于 `git diff` 原文切片 + `git apply --cached`，二进制文件与重命名走整文件暂存。
- 不做 rebase、submodule、LFS。
